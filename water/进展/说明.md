## slxpy 工具链简介

### 什么是 slxpy

**slxpy** 是一个用于将 Simulink 模型转换为 Python 可调用扩展模块的工具链。它提供了从 Simulink 模型到 Python 环境的完整编译和绑定流程，使强化学习框架（如 GOPS）能够直接调用 Simulink 模型进行训练和验证。

### slxpy 的核心功能

| 功能模块                    | 说明                                                                                                    |
| --------------------------- | ------------------------------------------------------------------------------------------------------- |
| **Simulink 代码生成** | 调用 MATLAB/Simulink 的代码生成工具，将`.slx` 模型转换为 C/C++ 代码                                   |
| **环境包装生成**      | 自动生成符合 Gym/Gymnasium 接口规范的环境类（RawEnv、GymEnv），提供`reset()` 和 `step(action)` 方法 |
| **Python 绑定**       | 使用 pybind11 将 C/C++ 代码绑定到 Python，生成`.pyd` 扩展模块，使 Python 能够调用高性能的 C/C++ 代码  |
| **配置驱动**          | 通过`model.toml` 和 `env.toml` 配置文件灵活控制生成流程                                             |

#### 环境包装生成（Env Wrapper Generation）

**通俗解释**：为 Simulink 模型"穿上一件 Python 的外衣"，让它看起来和行为都像一个标准的强化学习环境。

**详细说明**：

- **为什么需要包装**：Simulink 生成的原始 C/C++ 代码只提供底层的模型计算功能（如 `initialize()` 和 `step()`），没有遵循强化学习框架期望的标准接口
- **RawEnv**：slxpy 自定义的基础环境包装，提供最简化的 `reset()` 和 `step(action)` 接口，直接返回原始状态和奖励。**这是 slxpy 特有的中间层，并非强化学习通用标准**
- **GymEnv**：符合 **Gymnasium 标准规范**的环境包装，提供：
  - `observation_space` 和 `action_space` 定义
  - `reset(seed=None, options=None)` 返回初始观测和信息字典
  - `step(action)` 返回五元组 `(observation, reward, terminated, truncated, info)`
  - 支持 seeded reset 确保实验可复现

**关于通用性的说明**：

| 环境类型         | 是否强化学习通用标准 | 是否 GOPS 统一接口 | 说明                                                    |
| ---------------- | -------------------- | ------------------ | ------------------------------------------------------- |
| **RawEnv** | ❌ 否                | ❌ 否              | slxpy 自定义的轻量级包装，仅用于 slxpy 内部测试和调试   |
| **GymEnv** | ✅ 是                | ✅ 是              | 遵循 Gymnasium 0.26+ 标准接口，是强化学习领域的通用标准 |

**GymEnv 的通用性**：

- **跨框架兼容**：Gymnasium 接口被绝大多数现代强化学习框架支持（包括 GOPS、Stable Baselines3、RLlib 等）
- **标准接口**：`reset()`/`step()` 方法签名、返回值格式均遵循 Gymnasium 规范
- **空间定义**：`observation_space` 和 `action_space` 使用 Gymnasium 的 Space 类定义

**GOPS 中的使用方式**：

- GOPS 通过 `env_creator()` 函数统一管理环境创建
- GOPS 支持多种环境接口（包括旧版 Gym、Gymnasium、自定义接口）
- 对于 slxpy 生成的环境，GOPS 在入口层（`simu_rlwatertank02.py`）进行了额外适配：
  - 将 Gymnasium 五元组 step 转换为 GOPS 期望的四元组（合并 terminated 和 truncated 为 done）
  - 补充 `seed()` 方法以兼容旧版 Gym 语义
  - 管理 TimeLimit 包装层

**作用**：让 GOPS 等强化学习框架能够像使用其他标准环境一样使用 Simulink 模型，无需关心底层实现细节。

#### Python 绑定（Python Binding）

**通俗解释**：为 C/C++ 代码"修建一座通往 Python 的桥梁"，让 Python 代码能够调用 C/C++ 编写的函数和类。

**详细说明**：

- **为什么需要绑定**：C/C++ 代码运行速度快但无法直接被 Python 调用；Python 代码灵活但速度较慢
- **pybind11**：一个开源库，用于创建 C++ 代码到 Python 的绑定接口
- **`.pyd` 文件**：Python 扩展模块（Windows 平台），本质是编译后的二进制代码，可以像普通 Python 模块一样被 import

**技术原理**：

1. slxpy 使用 pybind11 为每个 C++ 类和方法生成 Python 包装函数
2. 这些包装函数负责处理 Python 对象和 C++ 对象之间的类型转换
3. 最终生成的 `.pyd` 文件可以被 Python 解释器动态加载

**作用**：结合了 C/C++ 的高性能计算和 Python 的灵活性，使强化学习训练既能利用 Simulink 模型的精确计算，又能享受 Python 生态的便利。

### slxpy 工作流程

```
Simulink模型(.slx)
        ↓
  [slxpy代码生成]
        ↓
   C/C++源代码(model/*.cpp, *.h)
        ↓
  [pybind11绑定]
        ↓
   Python扩展模块(.pyd)
        ↓
  [Gym环境包装]
        ↓
   Python Gym环境
        ↓
   GOPS强化学习训练
```

### 关键配置文件

**1. `model.toml`** - 模型级配置：

- 指定 Simulink 模型名称
- 配置求解器类型（如 FixedStepAuto、ode4 等）
- 启用/禁用特性（连续时间、复数运算、非有限数支持等）
- 设置 C++ 类名和命名空间

**2. `env.toml`** - 环境级配置：

- 定义 Gym 接口的端口映射（Action、State、Reward、Done）
- 配置 action/observation space 的类型、范围、形状和数据类型
- 设置 reward 范围
- 定义 reset 时的随机参数初始化逻辑

### slxpy 在本项目中的作用

在 `rlwatertank02` 接入 GOPS 的过程中，slxpy 承担了以下关键任务：

1. **模型编译**：将 `rlwatertank02.slx` 编译为 C++ 类 `rlwatertank02_class`
2. **环境生成**：自动生成 RawEnv 和 GymEnv 包装类
3. **接口适配**：实现 Gymnasium 标准的 `reset()`/`step()` 接口
4. **随机种子支持**：实现 seeded reset 以确保实验可复现

### 测试中发现并修复的问题

1. slxpy GymEnv 的 `step()` 返回五元组 `(obs, reward, terminated, truncated, info)`，GOPS 单环境 wrapper 期望四元组 `(obs, reward, done, info)`。入口中增加适配器，将两类终止合并为 `done`，并保留 `TimeLimit.truncated`。

3. GOPS 训练器会先调用 `env.seed(seed)` 再调用 `reset()`，适配器已补充这一 seed 传递语义并验证复现成功。

## 阶段 10：选择算法并建立训练入口

首条训练路线采用模型自由算法 DDPG、MLP 网络和 `off_serial_trainer`，不需要额外实现可求导 `env_model`。

新增训练脚本：

```text
example_train/ddpg/ddpg_mlp_rlwatertank02_offserial_slx.py
```

脚本包含环境、DDPG actor/critic、串行 sampler、replay buffer、evaluator、checkpoint、TensorBoard 数据转 CSV 和绘图流程。最小流程已通过显式命令行参数完成 5 次迭代冒烟验证；按用户后续要求，脚本正式默认值改为 `max_iteration=1500`。

根据 `CreateSimulinkEnvironmentAndTrainAgentExample.mlx`，已完成以下参数映射：

| MATLAB 示例                          | GOPS 实现                                                       |
| ------------------------------------ | --------------------------------------------------------------- |
| actor/critic 隐藏层`[25,25]`、ReLU | `policy_hidden_sizes=[25,25]`、`value_hidden_sizes=[25,25]` |
| actor 学习率`1e-4`                 | `policy_learning_rate=1e-4`                                   |
| critic 学习率`1e-3`                | `value_learning_rate=1e-3`                                    |
| DiscountFactor`1.0`                | `gamma=1.0`                                                   |
| GradientThreshold`1`               | DDPG actor/critic 均启用梯度范数裁剪`1.0`                     |
| ExperienceBufferLength`1e6`        | `buffer_max_size=1_000_000`                                   |
| MiniBatchSize`400`                 | 正式训练可设`replay_batch_size=400`；冒烟测试使用 `16`      |
| 噪声标准差`0.3`                    | 物理噪声`0.3`，归一化后为 `0.003`                           |
| 噪声衰减率`1e-5`                   | `GaussNoise` 支持并启用逐采样衰减 `1e-5`                    |
| `Ts=1 s`、`Tf=200 s`             | `max_episode_steps=200`                                       |
| 每次评估 5 回合                      | `num_eval_episode=5`                                          |

MATLAB 的 `MaxEpisodes=5000` 和每 10 回合评估不能直接等同于 GOPS 的 `max_iteration`/`eval_interval`，因为 GOPS 每次 iteration 采集 `sample_batch_size` 个 transition，且回合可能提前终止。当前正式默认值为 `max_iteration=1500`、`sample_batch_size=8`，即预热后约再采集 12,000 条 transition；`eval_interval=100`，最多触发约 15 轮异步评估，每轮 5 回合。MATLAB 的 `StopTrainingValue=3000` 在当前 GOPS 串行 trainer 中没有直接对应的自动停止接口。

GOPS 当前采用以下替代机制：

1. `max_iteration=1500` 作为硬停止条件；
2. 每 `eval_interval=100` 次更新进行一次评估；
3. trainer 持续比较平均评估回报并保存更优的 `apprfunc_*_opt.pkl`；
4. 每 `apprfunc_save_interval=300` 次更新保存普通 checkpoint；
5. 用户通过 TensorBoard/CSV 观察评估回报，必要时手动停止。

动作策略采用：

```text
策略动作：[-1,1]
        ↓ GOPS ScaleActionData
物理 Action：[-100,100]
```

探索噪声按 MATLAB 示例设置为物理标准差 `0.3`，在 `[-100,100]` 动作映射下对应归一化标准差 `0.003`，并按 `1e-5` 逐采样衰减。
