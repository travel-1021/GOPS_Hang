# rl_water 后续训练计划

## 当前基础

`gops/env/env_matlab/resources/simu_rl_water/` 中的训练资源已经完成基础验证：

- `rl_water.cp38-win_amd64.pyd` 可在 `gops_env` 中导入。
- `GymEnv.reset()` 与 `GymEnv.step()` 可以正常执行。
- Action 为形状 `(1,)` 的 `float64`。
- State 为形状 `(3,)` 的 `float64`。
- Reward 为 `float64`，Done 为 `bool`。
- 模型采样时间为 1 s。

## 阶段一：接入 GOPS 环境工厂

- [ ] 新建 `gops/env/env_matlab/simu_rl_water.py`。
- [ ] 在入口中加载 `resources/simu_rl_water/rl_water.cp38-win_amd64.pyd`。
- [ ] 提供 GOPS 环境工厂所需的 `env_creator` 接口。
- [ ] 保留底层环境的 observation space、reset、step 和 close 行为。
- [ ] 设置单回合最大步数为 200，对应 `Tf=200 s`、`Ts=1 s`。

完成判据：可以通过 GOPS 的 `create_env` 使用 `env_id="simu_rl_water"` 创建环境。

## 阶段二：确定动作范围与缩放

- [ ] 确认 Action 对应的物理量、单位及有效范围。
- [ ] 将训练使用的动作空间设置为有限范围。
- [ ] 若采用 `[-100, 100]`，确认该范围不会引起明显的非物理响应或数值发散。
- [ ] 若启用 `action_scale=True`，确认策略动作 `[-1, 1]` 能正确映射到物理动作范围。
- [ ] 根据动作缩放重新计算探索噪声的归一化标准差。

完成判据：策略输出、GOPS 缩放后动作和 Simulink 实际输入三者的数值关系明确且经过测试。

## 阶段三：准备训练脚本

- [ ] 以现有 DDPG 训练脚本为基础创建 `simu_rl_water` 对应脚本。
- [ ] 将默认 `env_id` 设置为 `simu_rl_water`。
- [ ] 设置 `max_episode_steps=200`。
- [ ] 检查算法自动识别到 observation dimension 为 3、action dimension 为 1。
- [ ] 设置独立的日志、模型和评估结果目录，避免覆盖旧实验。
- [ ] 固定随机种子，保证初步测试可复现。

建议首先对照 MATLAB 示例检查以下参数：

| 参数 | MATLAB 示例值 |
| --- | ---: |
| Discount factor | 1.0 |
| Replay buffer length | 1,000,000 |
| Mini-batch size | 400 |
| Actor learning rate | 1e-4 |
| Critic learning rate | 1e-3 |
| Gradient threshold | 1 |
| OU noise standard deviation | 0.3 |
| Noise decay rate | 1e-5 |

这些参数需要映射到 GOPS 的参数名称，不应假设两个框架中的默认值相同。

## 阶段四：环境冒烟测试

- [ ] 使用固定 seed 多次 reset，检查可复现性。
- [ ] 检查 `h_goal` 和 `h_initial` 始终位于 `(0, 20)`。
- [ ] 分别使用零动作、动作下界和动作上界运行若干步。
- [ ] 检查 State、Reward 和 Done 的形状与数据类型。
- [ ] 检查输出中是否出现 NaN 或 Inf。
- [ ] 检查水位越界时 Reward 和 Done 是否符合模型定义。
- [ ] 检查未提前终止的回合是否在 200 步被 TimeLimit 截断。

完成判据：不同 seed 和代表性动作下均能稳定运行，终止与截断语义正确。

## 阶段五：Simulink 与扩展一致性验证

- [ ] 在原 Simulink 模型和 Python 扩展中设置相同的 `h_goal`、`h_initial`。
- [ ] 向两者输入相同的固定动作序列。
- [ ] 逐步比较 State、Reward 和 Done。
- [ ] 记录允许的浮点误差，并调查超过误差阈值的步骤。
- [ ] 至少覆盖正常运行、水位下界终止和水位上界终止三类轨迹。

完成判据：两端轨迹在确定的数值误差范围内一致。

## 阶段六：最小训练测试

- [ ] 将 replay buffer 预热量和 batch size 临时调小。
- [ ] 只执行 5 至 20 次参数更新。
- [ ] 检查采样器、buffer、actor 和 critic 更新是否完整执行。
- [ ] 检查 actor loss、critic loss、Q value 等指标是否为有限数。
- [ ] 检查 checkpoint、TensorBoard 日志和评估输出能否生成。
- [ ] 从 checkpoint 恢复模型并运行一个闭环回合。

完成判据：短训练正常退出，产物完整，checkpoint 可以恢复并执行。

## 阶段七：正式训练与评估

- [ ] 恢复目标 replay buffer、batch size 和训练迭代数。
- [ ] 设置定期评估、checkpoint 保存和停止条件。
- [ ] 同时监控回报、回合长度、动作、水位和参考水位轨迹。
- [ ] 保存训练配置、随机种子、代码版本和模型文件哈希。
- [ ] 使用多个随机种子重复训练，避免只依据单次实验判断效果。
- [ ] 将训练策略与原 PI 控制器或 MATLAB 预训练策略进行对比。

完成判据：策略在独立评估回合中稳定跟踪目标水位，并满足终止率、跟踪误差和控制动作等预定指标。

## 推荐执行顺序

1. GOPS 环境入口。
2. 动作范围与缩放。
3. 环境冒烟测试。
4. Simulink 一致性验证。
5. 训练脚本适配。
6. 最小训练测试。
7. 正式训练与独立评估。
